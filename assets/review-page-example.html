二分查找的区间定义

区间是闭是开，决定 while 条件和指针更新——三者必须自洽。

一页速记

  1. 先声明区间语义：闭区间 [left, right] 里 right 是候选，半开区间 [left, right) 里 right 不是。
  2. 闭区间配 while (left <= right)，半开区间配 while (left < right)；写反了要么漏掉最后一个元素，要么死循环。
  3. 收缩不能原地不动：闭区间写 right = mid - 1，半开区间写 right = mid，两边都要跨过已经排除的 mid。
  4. 循环结束时 left 是第一个「不小于 target」的位置——这个不变量比返回值本身更值得记。
  5. 判据不是「mid 等不等于 target」，而是「每轮区间是否真的变小、被排除的元素是否真的不含答案」。

1用闭区间 [left, right] 时，循环条件应该写成什么？

对。闭区间里 right 仍是候选元素，left == right 时还剩一个元素没检查，所以必须用 <=。

用 < 会漏掉 left == right 那一次，而那正好是最后一个候选。漏元素的 bug 大多出在这里。

为什么

循环条件不是背下来的，是从「区间里还剩几个候选」推出来的：闭区间的长度是 right - left + 1，等于 1 时还有元素，所以条件是 left <= right。

2闭区间写法里，nums[mid] < target 时应该怎么收缩？

对。mid 已经判定过且小于 target，新区间从 mid + 1 开始，区间才真的变小。

mid 已经排除过了，必须跨过它。写 left = mid 区间原地不动，直接死循环。

为什么

收缩的唯一要求是「候选区间严格变小，且被排除的元素确实不含答案」。mid 既然已经比过，就不该留在区间里。

3循环结束时，left 的含义是什么？

对。left 左边全部小于 target，left 及右边全部不小于 target。target 不存在时，left 恰好是它该插入的位置。

left 不是「找到了」的位置。target 不存在时它恰好是插入位置，这才是能直接用的结论。

为什么

把不变量写下来：left 左侧全部 < target，right 右侧全部 > target。循环结束时不变量仍然成立，答案就落在边界上。

4判断二分写得对不对，最可靠的检查是什么？

对。区间必须严格变小（否则死循环），被排除的元素必须真的不可能含答案（否则漏解）。两条都成立，二分就成立。

跑几组数据只能证明这几组对。要看的是不变量：区间变小 + 排除正确。

为什么

二分只有两类 bug：区间没变小（死循环）和排除错了（漏解）。对着这两条检查，比跑一百组用例更可靠。
